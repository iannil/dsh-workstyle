# 工作方式主页 v4 · 功能规划（评审稿）

> 目标：把「工作方式」主页从**包内容目录**改成**工作方式控制台**。先定功能，再谈视觉。
> 状态：已实现（范围 A：控制台 + 规则/技能启停）。日期：2026-11-08。
> 验证：smoke 82 项、panel-render 44 项全过；真机复验看页脚 `home v4 · 2026-11-08`。

## 1. 问题定义

v3 去掉了营销文案，但主页仍然是「这个包有什么」：

- 四格数字 + 规则全文列表 + 技能 chips，**能看不能管**；
- 用户打开页面没有「下一步该做什么」；
- 规则只能采纳/撤销蒸馏建议，不能停用、编辑、排序；
- 技能只能看名字，不能启停；
- 没有「最近发生了什么」的反馈。

所以它仍然像介绍页。v4 的判断标准只有一条：**打开主页是为了做事，不是为了读介绍。**

## 2. 主页要回答的 3 个问题

1. 现在生效的是什么？健康吗？（包、版本、启用规则数、待办数、最近蒸馏）
2. 我现在该做什么？（审阅建议、补证据、蒸馏、导出）
3. 我怎么改？（启停规则/技能、编辑、切换包、分发）

## 3. 功能清单

### P0 · 本轮必须

| 模块 | 能力 | 依赖 |
| --- | --- | --- |
| 状态条 | 生效包、版本、启用/总规则数、技能数、最近蒸馏时间；异常时标红 | 现有 status |
| 待办条 | 待审建议 n、缺证据规则 n、最近蒸馏距今；点数字直达对应筛选 | status 增加 pendingCount / noEvidenceCount |

| 技能管理 | 搜索；逐条启停；展开看说明与来源 | 新增 toggle + overrides |

```

```

设计原则：

- **动作优先**：每个数字都是筛选入口；每个空状态都给下一步按钮。
- **渐进披露**：列表只放决策信息（标题、严重度、来源、启停），全文/证据按需展开。
- **一屏三块**：状态（我在哪）→ 待办（做什么）→ 管理（怎么改）。
- **不做营销**：没有 eyebrow、副标题、pack description、常显证据。

## 5. 关键交互

- **规则启停**：点复选框立即写 overrides，toast「已停用 先方案后实现，下一轮生效」；系统提示下一轮重建。
- **筛选与搜索**：筛选是互斥 chips；搜索同时匹配标题、正文、id；无结果显示「没有匹配的规则」+ 清除按钮。
- **待审建议**：待办条只算未处理数；采纳后该条置灰并显示「已采纳」，全部处理完显示「已清空」。
- **缺证据**：指无 `evidence` 字段的规则；点击筛选出这些规则，提示「补一条证据」。
- **技能启停**：只影响技能提供器后续加载；正在跑的任务不中断。
- **空状态**：
  - 无建议 → 「还没有蒸馏报告」+ [蒸馏证据]
  - 无规则 → 「这个包没有规则」+ [新建规则]（P1）
  - 无蒸馏 → 「先跑一次蒸馏」

## 6. 后端改动（小）

### 6.1 本地覆盖文件

`$DSH_HOME/workstyle/overrides.json`，按包隔离，不改 pack 文件：

```json
{
  "packs": {
    "fde-engineering": {
      "disabledRules": ["short-sentences"],
      "disabledSkills": ["fde-qa"],
      "updatedAt": "2026-11-08T09:40:00.000Z"
    }
  }
}
```

规则合并顺序：`pack.rules + adoptedRules` → 应用 disabled 过滤 → 系统提示只渲染启用的规则。
技能提供器同样过滤 disabled。

### 6.2 新端点

- `POST /api/dsh-workstyle/toggle`
  body `{ "kind": "rule" | "skill", "id": "<ruleId|skillName>", "enabled": false }`
  → 写 overrides、invalidate skills provider、返回最新 status。
- status 增量字段：
  - `rules[].enabled`、`rules[].origin`（`pack` / `distilled`）
  - `skills[].enabled`
  - `summary.enabledRuleCount`、`disabledRuleCount`、`pendingCount`、`noEvidenceCount`
- 工具对齐：`workstyle_toggle`（P0 可选，P1 必须），命令 `/workstyle off <ruleId>` / `/workstyle on <ruleId>`。

### 6.3 导出语义

导出仍输出 pack + adoptions，**不包含本地停用状态**；停用是本机偏好，不影响分发。若以后要「连偏好一起导出」，加 `--with-overrides`。

## 7. 验收标准

1. 首屏没有任何介绍性段落（自动化断言：无 subtitle、无 pack description、无常显证据）。
2. 打开主页后 ≤2 次点击可完成：停用一条规则、采纳一条建议、导出包。
3. 停用后 `/workstyle status` 立即返回 `enabled:false`；新建会话的系统提示不含该规则。
4. 重启 DeepSeek Harness 后停用状态保持。
5. `test/smoke.mjs` ≥ 65 项、`test/panel-render.mjs` ≥ 25 项全过。
6. 真机复验：重启后页脚出现 `home v4 · 日期`，截图存档到 `docs/verification/`。

## 8. 风险与不做的事

- **规则 id 冲突**：overrides 按 id 存；采纳时若 id 已存在则跳过，停用优先于采纳。
- **系统提示变化**：停用会改变正在跑的会话行为，toast 明示「下一轮生效」。
- **包不可变**：所有修改只写 overrides，不写 `pack/reference`。
- **旧 JS 未加载**：先加构建标记；若重启后仍无四格数字，先查 `dsh-client-modules` 的 combo rev / 缓存，不再盲改 UI。
- **本轮不做**：规则正文编辑、合规趋势、团队协作——避免一次改太多。
